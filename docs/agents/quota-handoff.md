# 官方额度与交接

此规则在本项目始终适用，不覆盖用户已经下达的暂停指令。

- 使用可用的 `get_usage_limits` 工具读取当前主机已登录 ChatGPT 账户的官方 Codex 额度。优先采用 `rateLimitsByLimitId`；剩余百分比为 `100 - usedPercent`，缺失值表示未知。检查适用的短周期、周周期及其他独立额度窗口，不能用目标 token 预算、上下文长度或第三方额度代替。
- 每次开始开发、启动一批子代理、合并/提交任务以及结束长任务时检查。持续工作期间尽量每五分钟检查一次；仅在代理正在运行时主动调用，不声称后台实时监控。供应商是否为官方无法确认时，明确说明此读数仅为官方账户额度。
- 任一适用窗口剩余不超过 10% 时提前更新仓库检查点，减少新并行任务，预留交接空间。
- 任一适用窗口剩余不超过 5% 时，先通知并要求所有写入代理在安全检查点停止，保存各工作树现有成果。不要为了交接而仓促完成或合并功能；WIP 提交明确标注未完成，未知或用户改动不擅自提交。
- 在当前官方会话输出交接摘要，同时保存到根目录 `HANDOFF.md`：当前进度、待办、关键决策、未完成项，以及集成分支/HEAD、全部未合并分支/工作树、验证对应的提交和未验项、已启动进程、暂停原因和下一步。区分实现完成、模拟验证与真实业务验收；来源无法核实的代码标为未知。
- 检查工作区及未提交内容，保留所有工作树和未合并成果；不 reset、删工作树或清洗原始会话历史。摘要不包含密钥、认证信息或学生隐私原文。保存完成后停止开发，等待用户决定供应商切换或额度恢复后的下一步。
- 若工具不可用、读数过时或检查间额度突降，明确报告无法可靠判断；主动保存当前摘要，不能假称未触发，也不能保证一定在耗尽前完成。其他会话/并发代理共享账户额度，单次检查不构成实时保证。
- 跨供应商继续时推荐新会话读取仓库交接文件及真实 Git 状态；是否创建新会话由用户明确指示，不自动从混合历史 fork。
- 达到5%停止线时，交接文件和本地提交保存后，按 `github-sync.md` 集中同步相关分支并核实远程。平时及10%预防检查点只本地保存，不触发上传。若仓库或认证缺失，明确写入“仅本地保存、尚未推送”，不要为等待网络耗尽剩余额度。
