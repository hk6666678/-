# GitHub 固定同步

用户已要求本项目固定提交到 GitHub。此规则始终适用，不覆盖用户的开发暂停指令，也不代表可以自行选择账号、仓库或公开代码。

- 用户指定仓库后核对 owner/repository 与现有 origin，配置正确的远程地址；已有不同远程时保留并报告，不静默替换。当前尚无远程地址，需要用户提供完整 GitHub 仓库 URL，或账号／组织名与拟建仓库名。是否新建仓库、可见性由用户决定。
- 功能验证通过后，将明确属于本次任务的代码与验收记录提交到相应分支，随后正常 push；合并到 integration/aqp-trial 后也同步集成分支。不需要再次询问已经授权的普通提交与推送。
- 低额度交接时，先保存 HANDOFF.md 和各工作树成果，再同步集成分支以及相关未合并分支，包括明确标注未完成的 WIP。不能只推 main 或强行合并半成品。记录本地 HEAD、远程分支及同步结果。
- 首次推送前检查已跟踪及待提交文件，排除认证信息、密钥、真实学生数据、论文原件、业务数据库、备份归档和私有日志。合成测试夹具需明确标注；不把 git add 全部文件当作无条件默认动作。
- 认证优先使用已有 Git 凭据、SSH 或用户在本机完成的登录。不要求在聊天中发送密码、PAT、私钥；认证失效时指出缺少什么并指导本机登录。
- 普通 push 后核对远程目标分支是否指向预期提交。推送失败时保留本地提交和工作树，报告原因，不能把本地 commit 说成 GitHub 已同步。
- 不使用 force push，不删除远程分支，不擅自公开仓库、改仓库权限或合并受保护分支。远程存在新提交时先读取并检查差异，按当前分支工作流处理冲突，保留双方成果。
- 仓库或登录信息未齐时，可先完成已授权的本地提交并标记待同步；不恢复用户已暂停的功能开发。当前仓库无远程，本规则的首次远程同步尚未完成。
