# 导师与课题组关系及事实口径

导师业务目录使用工号或业务导师编号，课题组使用独立业务编号。目录记录与登录账号、账号学生绑定分别管理，创建目录或关系不产生任何授权。

`mentor_groups` 的维护、查看、分析和身份展示分别授权；学生关系同时检查学生当前院系专业、导师目录及课题组目录范围。具有导师角色的账号还必须满足显式账号学生绑定交集。每次读取及确认导入重新检查当前权限。

关系使用严格 YYYY-MM-DD 起止日期，结束日期可空，结束不得早于开始。同学生、导师、课题组三元组日期区间含边界，不允许重叠。不同导师或课题组的并行关系不自动判定错误。更正须提供当前版本和依据；保存追加版本历史及审计，不删除历史。

标准 Excel 提供导师、课题组及学生关系三种模板。上传先校验整批，预览不写入业务目录和关系。确认时重新核对上传人、来源、文件和学生/目录/关系当前状态，状态变化要求重新预览。任一行无效或重复则整批不写入；更正走独立带版本的更正入口。批次保留原始文件、来源部门、上传账号及确认状态，审计记录写入对象。

事实查询须指定关系统计日期，可按导师或课题组筛选。学生数按当日有效且当前获准查看/分析的关系去重。科研论文、专利、获奖项目和会议按当前有效成果业务记录去重，参与学生人数去重；复用成果列表的当前学生身份及院系专业匹配策略，并要求相应成果类别的查看和分析权限。下钻显示相应成果编号、标题、版本与授权参与人数；不显示未获授权参与人。关系日期不代表成果发生日期，当前统计不推断成果归属期间。

毕业和延期缺少已确认业务口径与必要事实，返回 `missing` 及原因，不能作为零值、预测或导师优劣排名。

验证均使用明确合成数据；API覆盖目录授权/脱敏、日期格式/顺序、重叠冲突、乐观版本、更正历史、四类Excel成果导入与事实下钻、撤权即时生效，以及目录Excel预览/确认。Chrome覆盖目录、关系、历史、事实下钻与撤权。真实业务数据和业务口径仍需用户验收。
