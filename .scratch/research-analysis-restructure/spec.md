# 研究分析重组与交互减负（阶段 1）

## 背景

用户反馈"研究分析"分组操作太多、弄不明白。对照《数智赋能拔尖创新人才培养质量教育教学研究系统方案（AQP-PGS）》六大模块梳理后确认的根源：

1. 10 个导航入口中混入大量数据维护操作（导师课题组 CRUD、成果作废、通过规则启用）；
2. "已发表科研论文/专利/获奖项目/会议"4 个入口复用同一组件（ResearchOutputs）；
3. 学位论文流程拆成三段（上传→打标比较→候选），靠手抄数字 ID（比较快照 ID）串接；
4. 每页都有"先读取再操作"前置按钮（读取规则/学生/历史快照等）；
5. 同一动作多页重复（专业筛选+读学生 2 处、业务确认表单 7 处、Excel 导入 3 处）。

## 方案（2026-11-18 用户批准）

按"数据管理 / 研究分析 / 业务规则 / 系统管理"重新分组导航；四个成果入口合并为带标签页的单入口；学位论文拆为"上传"（数据管理）与"质量"（研究分析）两页；消灭手输 ID（比较快照、候选结果、导师/课题组、比较论文版本全部改下拉）；删"读取XX"按钮改挂载自动加载；规则管理集中到新页 BusinessRulesPanel。

**不改**：权限模型、审计、业务确认与独立导出授权要求（只挪位置不取消）。

## 边界（阶段 1 不做）

- 不合并 MentorGroup 事实统计与课题组报告（阶段 2"导师效能"）；
- 不做拔尖人才识别仪表盘与 Agent 统一入口（阶段 3）；
- 不动本机 8000 演示服务、data/tongji-demo/、未跟踪截图与 artifacts/。
