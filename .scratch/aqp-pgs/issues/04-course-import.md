# 04: 课程导入与待关联记录

**Status:** resolved

**Specification:** [AQP-PGS 第一版开发规格](../spec.md)

**What to build:** 导入课程记录，查看学生课程明细和基础档案缺失时的待关联状态。

**Blocked by:** 03 基础信息导入与学生档案

**规格覆盖:** 用户故事 7、9、10、11、15、16、18、20、25；AC02、AC03、AC05、AC06、AC07。

## Acceptance criteria

- [x] 按课程模板和学号＋课程编号＋修读学期＋考核次数识别记录，合法空成绩与错误值分开。
- [x] 无基础档案时仅保存待关联业务数据；基础补齐后自动核对并关联，身份冲突转人工处理。
- [x] 已关联课程显示在档案；同课不同学期、重修和补考分别保留，重复提交不倍增。
- [x] 预览及处理状态计数互斥且总数一致，内容变化先显示待确认，不自动更新。
- [x] 在本任务涉及的页面、公开 API 和持久化行为间完成可演示闭环，权限与审计随该功能一起交付。
- [x] 使用已确认测试边界验证外部行为；测试数据清楚标为合成，测试替身不计真实模型验收。

## 实现约束

遵循 AQP-PGS 第一版开发规格、项目术语和架构决策；不扩大第一版范围。涉及的修订、证据与原始文件不得静默覆盖。本任务拆分已于 2026-11-11 经用户确认发布。任务可执行性取决于前置任务及注明的外部条件，不由分诊标签单独决定。


## Answer

实现课程v1 Excel模板、60,000行上限的预览、显式确认、互斥状态、重复跳过与冲突保留；无基础档案时保存待关联课程，不创建学生。来源学院/专业在模板选填列或上传表单明确，基础档案存在时可使用实际档案范围。基础补齐后系统核对姓名及学院专业，冲突不合并。档案展示当前可见课程和来源，当前权限即时控制字段和范围。

后续06/07契约：`course_records` 按 student_number/course_code/term/attempt 唯一，payload保留中文标准字段（原始成绩合法空字符串），student_id可空；state为pending/linked/conflict，version初始1，source_row_id指向import_rows；原始行raw_json与normalized_json、batch/source_department/上传人/哈希/原始xlsx均保留。课程批次使用 `/api/imports/courses/{id}` 和 `/confirm`，不得由basic批次处理器处理。预览冲突附existing版本和脱敏数据；06负责在线纠错及人工确认，07负责更正/作废及后续修订历史，当前功能绝不自动覆盖已有课程。`reconcile_courses(db, actor)`由基础确认触发，不要求触发人持课程维护权；事件审计记录触发主体。

验证：公开API覆盖空成绩、补考、待关联/自动关联、姓名冲突、范围拒绝、同文件冲突、完全重复、确认重试和来源脱敏；Chrome覆盖课程预览/确认/基础补齐/刷新关联，独立合成Excel夹具避免跨场景污染。真实业务数据验收仍待实际样例。
