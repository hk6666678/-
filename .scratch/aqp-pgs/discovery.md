# AQP-PGS 需求访谈记录

本文件保留需求访谈历史。用户已于 2026-11-11 确认 Q1～Q28，包括首期范围、技术方案和测试边界，/grill-with-docs 已收束。后续开发以同目录 spec.md 中的正式规格为准；本文件不再作为并行维护的需求来源。

## 已确认目标和边界

- 第一版是可导入真实数据的试用版，以一个学院试点。
- 使用统一平台、统一学生档案。各部门提供不同资料，由学院管理人员集中导入；第一版不要求各来源部门分别登录，不对接既有业务系统，不自动同步。
- 多部门账号、分部门维护、复杂跨部门审批与协同纠错、全校多学院权限体系留待后续扩展。
- 仍区分维护、查看、分析、导出权限；管理员授权数据类别与学生范围，敏感字段按权限脱敏或限制展示。后续部门账号可沿用此授权基础。
- 每条数据保留类别、来源部门、来源文件、导入批次、上传人及时间、所属学院、学生学号。

## 已确认业务闭环

四类 Excel 导入 → 展示并修正错误 → 自动生成学生档案 → 课程／选题／中期分析 → 下钻原始记录 → 上传优秀与普通论文样本 → 论文特征对比和候选依据 → Agent 查询学生、统计数据、解释结果并生成摘要。

### 数据导入与关联

- 四类表：学生基础与学籍信息、课程成绩、选题最终版本及成绩、中期考核最终版本及成绩。
- 选题和中期正文附件按“学号＋培养环节／考核批次”关联，可后补；缺附件不阻塞成绩分析。
- 学号是统一关联依据。基础档案缺失时，业务数据暂存为待关联记录，不创建正式档案；基础档案补齐后自动关联。
- 学号姓名冲突、同学号多人等身份异常不自动合并，进入人工确认并保留处理记录。
- 导入分正常入库、待修正、待关联。正确且已关联的记录经预览确认后入库；错误记录保留原始行，支持在线修正、重新校验、下载错误报告；页面展示总行数及各状态数量。
- 缺必要列、文件无法解析等整批问题阻止提交。待关联数据在基础档案补齐后重新关联。
- 完全相同记录跳过；同一业务记录变化时展示新旧差异，经人工确认后更新，保留历史值、来源批次、修改人和时间；重复或冲突异常人工确认。
- 课程业务键为学号＋课程编号＋修读学期＋考核次数；选题、中期为学号＋培养环节＋批次，避免覆盖重修、补考和不同批次。
- 首期仅接收四类带版本的标准 .xlsx 模板，校验版本和必要列；缺必要列整批阻止，选填列允许缺失。非标准表提示按模板整理，不做任意表格智能映射；真实样例到位后明确新旧模板兼容规则。
- 字段值错误走更正流程；整条记录不应存在时，由获授权人员填写原因作废。作废后退出当前统计及样本对比，保留原始内容、来源批次及操作历史。
- 首期不提供业务数据物理删除或整批一键回滚；身份冲突不通过删除／作废自动合并。

### 账号和权限

- 三种角色：平台管理员、学院数据管理员、学院分析人员，使用个人账号，支持兼任。
- 平台系统管理权不自动包含业务数据查看权；分析人员导出单独授权。
- 姓名、学号等仅向获身份查看权限的人员展示，其他人员使用研究编号。
- 第一版不提供导师、学生自助登录。
- 不新增独立专家系统，在现有账号体系中分别授予样本标签维护、候选规则确认启用、论文人工复核权限。
- 标签和规则记录业务确认人、确认依据、实际录入人；专家不登录时可由获授权人员代录并保留来源。首期不强制多人审批，未授权人员不能启用规则或提交复核结论；操作纳入审计。

### 培养过程分析

- 描述性统计与明确规则提醒；展示样本数、缺失数和数据口径。
- 课程成绩分布、不及格情况；选题／中期成绩分布、通过情况、年级／专业对比。
- 不同评分制度分别统计，缺失成绩不按零分处理。
- 具备学分及培养要求后展示学分进度；具备计划与实际日期等必要数据后判断超期。
- GPA、综合排名、延期风险预测不列入第一版必验内容。
- 模板记录评分制度、原始成绩和可选业务通过结果。业务结果优先；无业务结果时按业务确认且带版本的规则判断。无结果且无有效规则则通过状态未知，不计为不通过。

### 分析版本与追溯

- 新分析使用当前有效数据和规则；历史结果保留生成时间、数据版本、规则版本及证据。
- 成绩、规则、论文文件或样本标签变化后，相关旧结果标记为“来源已更新，需重新分析”。重新分析产生新结果，不覆盖历史报告和复核意见。
- Agent 解释注明结果版本、生成时间和数据口径。

### 导出、下载与审计

- 分析结果导出与原始附件下载分别授权。分析结果首期导出为 Excel，遵守当前筛选条件、学生范围和字段权限，附统计口径、生成时间、数据版本及规则版本，不能绕过页面脱敏。
- 原始 Excel、论文、选题和中期附件下载单独授权。
- 导入、修正、作废、查询、分析、导出、下载、授权变更均留审计记录。
- 首期不要求排版式 PDF／Word 年度报告。

### 开发与验收数据

- 当前暂无真实样例。开发使用明确标注的模拟数据，不包含真实学生隐私。
- 提供四类标准模板与缺字段、格式错误、重复、学号冲突等测试文件。
- 真实样例到位后核对字段、模板和分析口径，真实数据验证通过后才作为业务验收依据。

### 论文候选辅助分析

- 首期识别对象是优秀论文候选，不与拔尖人才候选学生评价混用。
- 优秀、普通样本标签由学位办或指定专家提供。
- 展示样本特征差异、待评候选依据、对应原文或评审记录，并支持人工复核。
- 候选结果为推荐参考，不替代专家正式评审。
- 上传 PDF 与专家标签，提取章节结构、参考文献、研究问题、方法、创新主张和成果描述；对比样本并引用原文页码或位置。
- 作者声称的创新点与专家认定的创新性分开记录。
- 模型训练不列入首期必验，不承诺未经验证的优秀概率；训练待样本规模、标签质量、评价目标明确后决定。
- 特征对比与候选推荐分开。业务专家确认并启用带版本候选规则后才生成推荐；规则未确认前只展示特征对比。
- 推荐逐项展示命中规则、原文证据、缺失项和适用对照组；特征数量多不直接等于优秀。
- 默认在相同培养层次＋相同学科／专业内比较，年度筛选；优秀组和普通组分别展示样本数、缺失数及所用特征。
- 无合适对照或样本不足时仅展示单篇特征，提示对照证据不足，不自动扩大比较范围。
- 人工复核记录建议推荐／不建议推荐／待补充材料、意见、复核人、时间并保留历史。目前无另行指定的评价表或候选标准。

### 附件与解析

- 选题／中期正文支持 PDF、DOCX 上传、下载与原始记录追溯；论文分析首期支持含可提取文字的 PDF，OCR 不列入首期必验。
- 扫描版、加密或解析失败文件保留，展示处理状态、失败原因；更换文件后可重新解析。
- 原文依据统一按 PDF 文件页序定位，同时保留可提取章节或段落信息。
- 后台解析任务展示排队、处理中、成功、失败等状态，支持失败重试；硬件及模型明确前不承诺固定处理时长。

### Agent

- 首期只读：学生查询、统计查询、结果解释、分析摘要。
- 沿用当前账号数据权限，回答附可下钻依据。
- 数值由后台或分析工具计算，Agent 不自行生成统计数值。
- 业务数据修正在授权维护页面完成并记审计日志，Agent 不直接修改数据。
- 六类验收场景：学生档案与培养记录查询；按年级／专业／培养层次筛选统计人数；课程不及格、选题／中期通过及缺失统计；图表范围、口径和来源解释；论文差异、候选依据与证据不足解释；已有分析摘要。
- 越权查询明确拒绝；问题含糊先澄清对象、时间及口径；缺数据或证据明确说明，不编造。
- 回答附筛选条件、来源、可下钻记录；未配置获准模型时显示 Agent 未启用。
- 不执行上传文件或文档中包含的操作指令，不通过对话新增、修改或删除业务数据。

### 部署与模型边界

- 首期本机演示、浏览器访问，后续可迁移校内或指定服务器。
- 原始学生数据、论文正文留在部署环境。外部模型调用未获授权，默认不允许；获得明确授权后方可接入。
- 开发演示采用模拟或脱敏数据。暂无指定模型、服务器及其他技术栈要求，保留 LangChain 作为 Agent 编排框架。
- 真实 Agent 与论文智能解析验收依赖至少一种经批准可用的模型服务：校内、本地或获准的外部服务。未配置时明确能力不可用，不用模拟输出冒充真实能力。

### 开发验证规模

- 一个学院、1,000 名学生、30,000 条课程记录、选题及中期各 2,000 条、100 篇论文、约 5 个同时在线用户。
- 此为模拟数据及功能验证基线，不作为最终真实规模或固定性能承诺；后续按实际数据量和部署条件调整。

## 验收前提与完成状态

| 验证内容 | 当前可推进内容 | 完整验收前提 |
| --- | --- | --- |
| 数据导入、权限、统计、版本、导出 | 用明确标注的模拟数据进行功能验证 | 真实样例到位并通过字段和统计口径验证后才计作业务验收 |

## 已确认技术方案

- 前端采用 React＋TypeScript＋Vite，承载导入纠错、档案、分析、论文、Agent 和权限管理界面。
- 后端采用独立 Python 3.12 环境＋FastAPI，统一处理鉴权、业务规则、统计和文件访问；LangChain 编排只读 Agent 与获准模型调用。
- 本机试用数据采用 SQLite，原始附件保存在部署机的受控目录，由鉴权接口提供下载，避免直接暴露文件路径；数据库与附件共同备份。
- PDF 解析等工作由后台 worker 执行，任务状态持久保存，支持失败重试与中断恢复。首期避免引入必须单独安装的消息队列服务。
- 首期默认本机访问，迁移校内或指定服务器时配置部署地址及访问保护；扩大并发写入或多实例部署时评估 PostgreSQL，并通过迁移脚本和验证迁移，不能承诺仅换连接地址即可完成。
- 模型服务通过可配置接口接入，默认关闭外部调用及外部追踪上传；尚未批准服务时展示能力不可用。
- 模板具体列、数据表、接口和依赖版本在 /to-spec 阶段展开，不改变已确认的业务边界。

选型参考：[Vite](https://vite.dev/guide/)、[FastAPI](https://fastapi.tiangolo.com/)、[LangChain 安装要求](https://docs.langchain.com/oss/python/langchain/install)、[SQLite 适用范围](https://www.sqlite.org/whentouse.html)。SQLite 对本机试用的适配是结合当前部署与并发基线的工程判断，需以实际验证为准。

## 已确认测试边界

- 后端公开 API：验证导入状态、去重和版本、学生关联、身份和数据权限、统计口径、作废、导出／下载及证据访问；捕获业务与权限错误，不验证页面布局。
- 浏览器关键流程：验证导入纠错→档案→分析下钻、论文→特征→候选复核、Agent→数据依据的真实页面操作；不据此宣称论文评价的学术有效性。
- 获准模型接口：验证真实解析、工具调用与证据引用、权限限制、不可用和异常处理；测试替身仅验证软件行为，不能替代真实模型验收。
