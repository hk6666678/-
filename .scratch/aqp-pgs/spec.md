# AQP-PGS 第一版开发规格

Status: ready-for-agent

确认日期：2026-11-11。适用范围：一个学院、本机浏览器访问、可导入真实数据的试用版。

本规格将已确认的 Q1～Q28 转化为开发与验收约定。ready-for-agent 表示可以据此拆分和实现任务，不表示软件已经交付或真实业务验收已经完成。领域名称遵循项目术语表，架构遵循已确认的架构决策。

## Problem Statement

研究生基础信息、课程成绩、选题及中期考核材料来自不同部门，学院人员需要汇总文件、修正错误并确认同一学生的记录，才能分析培养过程。缺少统一的身份关联、来源记录和分析口径，会导致重复入库、错误覆盖、无法解释统计结果以及权限失控。

论文质量研究还需要比较已标注的优秀与普通样本，呈现可追溯的候选依据，由业务专家复核。用户希望通过对话查询学生、获取统计和解释分析，但不能让模型绕过权限、编造数值或代替专家作正式评审。

目前没有真实数据样例、已确认的候选规则或指定的获准模型服务。第一版需要用明确标注的模拟数据验证完整软件流程，并保留真实数据、专家规则和模型接入后的业务验收条件。

## Solution

提供一个统一平台，由试点学院管理人员收集各部门资料并集中导入。四类标准 Excel 经过预览、校验、纠错、去重和学生关联后，汇总到统一学生档案；用户在权限范围内分析课程、选题和中期，并下钻到原始记录。

论文模块保存 PDF、专家标签和文件版本，提取具有页序依据的特征，在相同培养层次和学科／专业的范围内比较。只有专家确认启用适用的候选规则后才生成推荐，并保留人工复核历史。LangChain 编排只读 Agent，数值来自受控业务工具，回答携带可查证的数据依据。

平台通过个人账号、三类基础角色与细分授权控制维护、查看、分析、身份展示、导出、原始文件下载及专家操作。所有业务数据保留来源、修订和作废历史，分析结果保留生成时的数据与规则版本。

功能入口包括账号与授权、数据导入与待处理记录、学生档案、培养过程分析、论文及样本管理、候选与人工复核、Agent、规则配置、审计与模型连接状态。入口数量不规定页面必须一一独立，最终页面围绕业务流程组织。

## User Stories

1. 作为平台管理员，我希望创建、停用个人账号并分配角色，以便试点人员使用各自身份操作。
2. 作为平台管理员，我希望一个人可以兼任多个角色，以便匹配学院实际分工。
3. 作为平台管理员，我希望系统管理权与业务数据查看权分开，以便账号管理不自动开放学生信息。
4. 作为平台管理员，我希望按数据类别、学生范围和操作类型授权，以便控制维护、查看与分析职责。
5. 作为平台管理员，我希望单独授予身份查看、结果导出和原始文件下载权限，以便控制不同形式的数据访问。
6. 作为平台管理员，我希望分别授权标签维护、候选规则启用和论文复核，以便在现有账号内承载专家业务。
7. 作为学院数据管理员，我希望下载四类带版本的标准模板，以便收集格式明确的资料。
8. 作为学院数据管理员，我希望导入时填写来源部门并保留上传信息，以便区分资料提供者和实际操作人。
9. 作为学院数据管理员，我希望校验文件类型、模板版本和必要列，以便阻止无法正确识别的整批文件。
10. 作为学院数据管理员，我希望预览导入结果和各状态数量后再确认入库，以便检查本次操作影响。
11. 作为学院数据管理员，我希望正确记录先入库、错误记录保留待修正，以便局部错误不阻塞全部业务数据。
12. 作为学院数据管理员，我希望看到错误原始行、字段与原因，以便定位问题。
13. 作为学院数据管理员，我希望在线修正并重新校验错误行，以便完成同一批次的纠错。
14. 作为学院数据管理员，我希望下载遵守字段权限的错误报告，以便线下整理问题。
15. 作为学院数据管理员，我希望业务数据缺少基础档案时进入待关联区，以便不创建虚假正式档案。
16. 作为学院数据管理员，我希望基础档案补齐后自动重新关联，以便汇总此前接收的业务记录。
17. 作为学院数据管理员，我希望学号姓名冲突进入人工确认并留痕，以便防止不同学生被错误合并。
18. 作为学院数据管理员，我希望完全相同的记录自动跳过，以便重复上传不重复计数。
19. 作为学院数据管理员，我希望同一业务记录变化时看到新旧差异并确认更新，以便防止无意覆盖。
20. 作为学院数据管理员，我希望不同修读学期、考核次数和批次分别保留，以便重修、补考和多次考核不互相覆盖。
21. 作为学院数据管理员，我希望更正保留原值、来源和修改信息，以便追查数据变化。
22. 作为学院数据管理员，我希望填写原因后作废不应存在的记录，以便停止使用错误数据并保留历史。
23. 作为学院数据管理员，我希望后补选题和中期附件，以便材料未齐时也能分析已有成绩。
24. 作为学院数据管理员，我希望附件关联到学号与明确考核批次，以便查看对应版本的正文。
25. 作为学院分析人员，我希望在统一学生档案中看到授权的基础信息和培养记录，以便理解同一学生的培养过程。
26. 作为学院分析人员，我希望按年级、专业和培养层次筛选，以便明确分析对象。
27. 作为未获身份查看权的分析人员，我希望以研究编号查看允许的数据，以便身份信息保持隐藏。
28. 作为学院分析人员，我希望查看课程成绩分布与不及格情况，以便发现需要关注的学习情况。
29. 作为学院分析人员，我希望查看选题和中期的成绩、通过状态及分组对比，以便分析培养环节。
30. 作为学院分析人员，我希望每项统计显示样本数、缺失数、筛选条件和分母，以便正确解释结果。
31. 作为学院分析人员，我希望不同评分制度分开统计，以便避免混用等级和数值成绩。
32. 作为学院分析人员，我希望优先使用业务提供的通过结果，以便尊重原业务结论。
33. 作为获授权的规则维护人员，我希望确认并版本化通过规则，以便在未提供业务结果时得到可解释判断。
34. 作为学院分析人员，我希望无通过结果又无有效规则时看到通过状态未知，以便不把未知算成不通过。
35. 作为学院分析人员，我希望仅在必要数据齐全时查看学分进度和超期判断，以便避免无依据提醒。
36. 作为学院分析人员，我希望从分析结果下钻到记录、批次和来源行，以便核验统计依据。
37. 作为学院分析人员，我希望看到结果生成时间及数据、规则版本，以便区分当前分析与历史结论。
38. 作为学院分析人员，我希望来源变化后旧结果标记待重新分析，以便发现已过时的结论。
39. 作为学院分析人员，我希望重新分析产生新版本并保留历史，以便比较和解释变化。
40. 作为论文维护人员，我希望上传含可提取文字的 PDF 及论文元信息，以便建立论文记录。
41. 作为获授权的标签维护人员，我希望录入优秀、普通样本标签及专家确认来源，以便形成有出处的对照样本。
42. 作为论文维护人员，我希望未标注的待评论文与已标注样本区分，以便不把未评定论文默认为普通样本。
43. 作为论文维护人员，我希望看到解析排队、处理中、成功和失败状态，以便了解处理进度。
44. 作为论文维护人员，我希望解析失败仍保留文件及原因，并支持替换和重试，以便修复材料问题。
45. 作为学院分析人员，我希望查看章节、参考文献、研究问题、方法、创新主张和成果描述，以便检查论文特征。
46. 作为学院分析人员，我希望每项可追溯特征引用 PDF 文件页序和可用段落，以便检查原文。
47. 作为学院分析人员，我希望区分作者创新主张与专家创新性评价，以便避免混淆证据性质。

50. 作为学院分析人员，我希望对照不足时只看到单篇特征和不足提示，以便不被不可靠推荐误导。
51. 作为获授权的规则确认人员，我希望确认并启用带版本的候选规则，以便推荐有明确业务依据。
52. 作为学院分析人员，我希望没有启用规则时仅展示特征对比，以便不生成无标准候选结论。
53. 作为学院分析人员，我希望候选推荐逐项展示命中规则、证据和缺失项，以便进行人工复核。
54. 作为获授权的复核人员，我希望记录建议推荐、不建议推荐或待补充材料及意见，以便留下明确业务结论。
55. 作为获授权的复核人员，我希望历史复核保留人员、时间和对应结果版本，以便后续分析不改写过去的判断。
56. 作为业务代录人员，我希望记录专家确认人、确认依据和实际录入人，以便专家不登录时仍有可追溯来源。
57. 作为学院分析人员，我希望通过 Agent 查询获授权学生的档案和培养记录，以便快速获取资料。
58. 作为学院分析人员，我希望通过 Agent 按年级、专业、培养层次筛选并统计人数，以便回答日常统计问题。
59. 作为学院分析人员，我希望通过 Agent 查询课程不及格、选题／中期通过及缺失情况，以便定位培养问题。
60. 作为学院分析人员，我希望 Agent 解释图表口径、范围和来源，以便理解系统计算结果。
61. 作为学院分析人员，我希望 Agent 解释论文差异、候选依据和证据不足，以便理解辅助分析的边界。
62. 作为学院分析人员，我希望 Agent 根据已有结果生成带引用的摘要，以便整理分析发现。
63. 作为学院分析人员，我希望问题含糊时 Agent 先澄清，以便避免选错对象或统计口径。
64. 作为学院分析人员，我希望缺数据、缺证据或模型不可用时得到明确提示，以便知道结果为何无法提供。
65. 作为平台管理员，我希望 Agent 拒绝越权和写入请求，并忽略上传材料中的操作指令，以便维持业务权限边界。
66. 作为获授权的分析人员，我希望导出与当前筛选及脱敏规则一致的 Excel，以便分享有清晰口径的结果。
67. 作为获授权的用户，我希望单独下载允许访问的原始文件，以便核验材料而不绕过授权。
68. 作为平台管理员，我希望查询授权范围内的审计记录，以便追查维护、访问、分析和授权操作。
69. 作为试用人员，我希望在本机启动平台并通过浏览器访问，以便开展首期演示。
70. 作为维护人员，我希望后台任务在重启后可恢复或安全重试，以便避免重复产出和丢失进度。
71. 作为维护人员，我希望成套备份和恢复数据库与附件，以便保留结果、版本和证据的完整联系。
72. 作为验收人员，我希望用标注清楚的模拟数据和错误文件验证流程，以便与真实业务验收分开。
73. 作为验收人员，我希望在真实样例和获准模型到位后验证实际效果，以便不把测试替身当成交付能力。

## Implementation Decisions

### 1. 架构与模块边界

- 前端使用 React、TypeScript、Vite；后端使用独立 Python 3.12 环境和 FastAPI；LangChain 承担模型及只读工具编排。
- 第一版采用单体业务服务、SQLite、受控本地附件存储和独立后台 worker。持久化任务由数据库记录，首期不要求额外消息队列服务。数据文件位于部署机本地，浏览器通过服务访问，不直接打开数据库。
- API 是主要业务边界。界面、Agent、导出与文件下载复用同一套权限、规则和记录查询能力。前端隐藏按钮不能代替服务端鉴权。
- 模块划分为账号与权限、导入与数据治理、统一档案、培养统计、附件与解析、论文比较与规则、人工复核、Agent、审计和后台任务。模块在一个应用中协作，首期不拆成部门独立服务。
- 数据修改使用短事务和版本冲突检查。SQLite 写入竞争、后台任务并发与重试须在约五个并发用户的基线下验证；不要在文件解析或模型等待期间持有数据库写事务。
- 数据库结构采用可追踪迁移；附件与数据库共同备份。扩大写并发或多实例部署时再评估 PostgreSQL，迁移需显式转换与一致性验证。
- 本机浏览器访问为默认方式。服务器部署需重新配置监听地址、访问保护、存储和模型连接；首期开发不自动发布公网服务。
- 实际依赖版本在实现时按兼容性验证并锁定；不将当前系统 Python 3.8 用作本应用运行环境。

### 2. 账号、身份与权限契约

| 基础角色 | 可授予的主要职责 | 不自动获得的权限 |
| --- | --- | --- |
| 平台管理员 | 账号、授权、系统配置与授权范围内的审计 | 学生业务数据、身份信息、原始文件 |
| 学院数据管理员 | 指定类别与范围的导入、纠错、更正、作废、附件维护 | 任意分析、导出、其他类别数据和原始文件下载 |
| 学院分析人员 | 指定范围的档案、分析、Agent | 身份展示、导出、原始下载、标签维护、规则启用、人工复核 |

- 角色提供可配置职责组合，最终权限由明确授权决定；支持兼任，不因职位名称隐式获得数据。
- 授权至少表达操作、数据类别和学生范围。首期使用试点学院范围及其内部必要筛选，保留学院归属，不扩展全校多学院管理产品。
- 账号为个人账号，支持登录、退出、停用和会话失效。身份由服务端会话确定，不能相信客户端传入的账号、学院或权限值。
- 身份查看权控制姓名、学号等字段；无该权时使用稳定研究编号。研究编号不是通行凭证，仍须检查对象权限。
- 每次请求都校验当前权限；历史结果、旧下载链接、模型工具及审计查询不能继续沿用已撤销的授权。
- 标签维护、通过规则维护、候选规则确认启用、人工复核均为明确业务授权。管理员分配权限，业务确认来源与操作人分别记录。
- 原始附件与原始 Excel 可能含身份和范围外记录。只有用户的原始下载权、身份权及数据范围覆盖文件内容时才允许原样下载；否则拒绝并可使用获授权的脱敏结果导出。原始 PDF 页预览同样受控，不能通过证据链接泄露身份。
- 上传纠错界面、错误报告、摘要、图表、模型输入、模型输出和审计展示遵守同样的字段及范围限制。

### 3. 领域数据与标准模板

业务实体包括个人账号与授权、来源部门、学生及基础信息修订、课程考核、选题考核、中期考核、导入批次与原始行、关联冲突处理、附件及文件版本、论文与样本标签修订、解析任务、特征与证据、规则版本、分析结果、人工复核和审计事件。每类历史对象有稳定标识，分析引用具体修订，而不是只保存当前值。

学生档案由成功确认的基础信息产生；学号按文本处理并保留前导零。学号是首期单学院学生关联键，另有内部稳定标识和研究编号。存在同号多人或身份不一致时不能自动合并。

四类模板统一采用带明确类型和版本的标准 .xlsx。模板必要列与单元格必填性分开定义：必要列不存在导致整批无法识别；成绩等允许为空的单元格进入缺失统计，不因空值被当成零。以下为首期标准字段约定，真实样例到位后须核对并通过模板版本管理调整。

| 模板 | 必要列 | 每行必须有效的值 | 选填列／允许补充的信息 |
| --- | --- | --- | --- |
| 学生基础与学籍 | 学号、姓名、所属学院、专业、培养层次、入学年份 | 学号、姓名、所属学院、专业、培养层次、入学年份 | 前置院校、入学日期、学制、入学方式、学习形式、学位类型、学籍状态、导师标识、导师姓名、研究方向、学籍异动类型及时间 |
| 课程成绩 | 学号、姓名、课程编号、课程名称、修读学期、考核次数、评分制度、原始成绩 | 身份核对字段、课程编号与名称、学期、考核次数、评分制度；原始成绩可空 | 业务通过结果、学分、课程类别、考核日期 |
| 选题最终版本及成绩 | 学号、姓名、考核批次、选题标题、评分制度、原始成绩 | 身份核对字段、批次、选题标题、评分制度；原始成绩可空 | 业务通过结果、计划日期、实际日期、评语、正文版本说明 |
| 中期最终版本及成绩 | 学号、姓名、考核批次、评分制度、原始成绩 | 身份核对字段、批次、评分制度；原始成绩可空 | 业务通过结果、计划日期、实际日期、评语、成果说明、正文版本说明 |

- 批次元信息包含模板类型及版本、来源部门、所属学院、上传人和时间、来源文件及校验标识。每条业务记录追溯到原始批次、工作表及行号。
- 对学生的已确认业务键为学号；课程为学号＋课程编号＋修读学期＋考核次数；选题、中期为学号＋培养环节＋考核批次。课程编号和学期使用明确规范值，无法识别时提示错误，避免无依据模糊合并。
- 评分制度标识包括数值制、等级制、通过／不通过等实际配置，保留原始文本。没有有效评分制度或格式不符属于待修正；合法缺失属于缺失数据，两者分开。
- 选填列缺失不会导致整批拒绝；首期不支持任意字段智能映射。模板版本不受支持时明确提示，不猜测旧列含义。新旧版本兼容通过显式转换约定验证。
- 附件通过维护入口后补并绑定到已有记录或待处理关联，不依赖 Excel 中的本机文件路径自动读取文件。选题／中期的绑定包含学号、环节和批次。
- 学分培养要求和通过规则经授权配置；缺要求时不推算完成率。导师等补充字段首期用于资料展示，不意味着新增导师效能评价模块。

### 4. 导入、冲突和关联

导入按上传、结构校验、逐行校验、关联与差异识别、预览、确认、提交处理。结构错误的批次不能提交；预览不修改正式业务数据。

| 预览／处理状态 | 含义与后续行为 |
| --- | --- |
| 可入库 | 校验通过且基础身份已确认，用户确认后创建正式记录或基础档案 |
| 待修正 | 格式、值域或逻辑错误；保留原始行，授权人员修正后重新校验 |
| 待关联 | 格式有效但无基础档案；保存待处理记录，不生成正式学生档案，不参与正式分析 |
| 待人工确认 | 身份冲突、同一业务键内容冲突，或已有记录变化尚未确认；显示差异并保留处理依据 |
| 重复跳过 | 与当前同业务键有效内容一致；记录本次上传事实，不新增业务修订 |
| 已入库 | 确认并成功写入正式数据，可追溯其来源与修订 |

- UI 可将待人工确认显示为待处理的独立子类，但每行在一次状态汇总中只计算一次。总行数与各互斥状态数量一致；整批结构错误单独展示。
- 初次批次确认可以提交可入库行，同时保存待修正、待关联及待人工确认行。之后的处理只提交已经修复并再次确认的记录，不能重复提交已完成行。
- 待关联行在初次确认时已授权保存；基础档案补齐后自动校验身份并关联。若姓名不一致或有其他冲突，转人工确认，不因学号相同强制关联。自动关联记录时间及触发来源。
- 重复检测按规范化业务值和业务键判断，保留原始文本。完全相同的重复文件或行不能使统计倍增；同键不同内容不按文件先后顺序静默覆盖。
- 差异确认基于当前有效版本；确认期间该记录已被他人修改时，提示重新检查，不能覆盖后发生的变更。
- 原始行不可被在线纠错改写；纠错保存新的修正值与操作记录。下载错误报告也需检查字段权限。
- 学生姓名更正与学号纠错必须通过身份确认过程；首期不提供自动合并两个正式学生档案的能力。
- 同一提交请求重试应返回既有结果或安全继续，不能重复落库。批次写入结果与行状态一致，失败不能留下无来源的正式数据。

### 5. 修订、作废、分析版本

- 更正产生业务修订，保留旧值、新值、原因／确认依据、操作人、时间和来源。当前有效版本供新分析使用。
- 作废要求单独授权和原因，整条记录退出当前分析，原内容和历史仍可由获授权人员追溯。禁止首期物理删除、整批回滚和通过作废自动合并身份。
- 原始文件、论文、标签、通过规则、候选规则及人工复核均保留版本关系。替换文件不能覆盖被历史证据引用的旧文件。
- 分析结果保存对象范围、过滤条件、统计时间、数据版本、规则版本、计算口径及证据集合。模型相关结果另存模型连接标识、模型版本／返回标识和解析配置版本，不保存访问密钥。
- 数据或规则变化标记依赖它们的旧结果为“来源已更新，需重新分析”；新分析生成独立结果。历史结果按当前用户授权展示，不能因为历史曾有权限而越权。
- 人工复核绑定具体结果、论文与规则版本。结果变旧后，历史复核仍可查但不能冒充当前版本的确认。
- 对暂未启用规则的纯描述分析，以“无适用规则”记录规则状态；不得伪造规则版本。

### 6. 培养过程统计

- 课程分析提供成绩分布和不及格情况；选题／中期提供成绩分布、通过情况以及按年级、专业、培养层次的筛选与分组。
- 默认考核统计以考核记录为单位，不同次数分别保留；学生人数对学号关联后的内部学生标识去重。界面标明单位，不默认选择最高分或末次成绩代表所有考核。
- 仅统计已正式入库且当前有效的记录。待关联、待修正、待人工确认及作废记录不纳入，排除情况可单独展示。
- 相同评分制度与可比课程／环节内计算分布；不混算等级制和百分制均值，不默认把不同总分转换为统一分数。
- 通过状态优先采用合法业务通过结果；未提供时使用已确认且适用的规则。均缺失则为未知；缺失成绩不记零分，未知不记不通过。
- 通过率明确为“通过数／已知通过状态记录数”，同步显示全部记录数、通过数、不通过数、未知数与缺失成绩数。已知状态为零时通过率显示不可计算，不显示零。
- 业务通过结果与规则推导可能不一致时保留业务结果优先的来源说明，不静默改写业务结论。
- 学分进度只有在学分、培养要求、通过及重复修读计入规则齐全时计算；否则展示已有数据与缺少条件。计划日期、实际日期等必要信息齐全时按已确认规则判断超期；未完成节点也须有明确截止与未完成状态才能提醒。
- 描述统计不自动解释为因果或预测，首期不生成 GPA、综合排名、延期风险概率或人才排名。

### 7. 附件、论文与后台任务

- 选题／中期支持 PDF 和 DOCX 的保存、关联、授权下载与历史追溯；首期不要求对这些 DOCX 进行论文智能分析。
- 论文分析对象为含可提取文字的 PDF，记录标题、关联学生、培养层次、学科／专业、年度及文件版本。元信息不完整时显示待补充，不猜测比较组。
- 未提供优秀／普通标签的论文是待评对象，不自动归为普通；标签由获授权人员录入，包含业务确认人、依据及实际录入人。
- 对文件进行类型与可解析性检查，不执行文档中的宏、嵌入程序或指令。扫描版、加密、损坏或无法提取文字的文件保留，显示具体原因；OCR 不在首期范围。
- 解析按排队、处理中、成功、失败展示，支持重试和替换文件后重新解析。重试记录尝试次数与原因，后台进程中断后可恢复，不能把同一结果重复发布为多个成功版本。
- 原始文件与每次解析结果关联；PDF 文件页序从 1 开始，保留可获得的章节／段落和证据片段。印刷页码可作为补充信息，不能代替文件页序。
- 基础文本和结构提取可在本地执行；语义特征需要获准模型时明确标记等待模型或失败，不能以模板填充冒充提取成功。各特征分别记录可用、缺失或失败，部分结果不能伪装为全部成功。
- 文件访问走受控业务接口。无法可靠脱敏的原始页面仅向拥有对应原始内容和身份权限的用户开放；其他用户可看获授权的脱敏证据摘要。

### 8. 论文特征、对照、候选及复核

- 特征包括章节结构、参考文献、研究问题、研究方法、作者创新主张、成果描述；每项保留来源、提取方式、文件版本和可核查位置。提取不到时显示缺失，不由模型补写不存在的内容。
- 专家认定的创新性作为独立业务评价及来源记录，不能由“作者声称有创新”转换而来。
- 默认比较组为相同培养层次＋相同学科／专业，年度作为筛选条件。缺分组信息或对照组时提示不足，不自动跨学科扩样。
- 两组展示样本数、缺失数、实际使用的特征和适用范围；被评对象不能作为自己的独立对照样本。缺特征不自动记零，也不将无法解析论文纳入该特征的有效分母。
- “样本不足”的业务阈值由专家在适用规则中确认，开发不自行设定足以支持推荐的数量。未确定阈值时只能描述现有样本，不据此宣称推荐证据充分。
- 候选规则是结构化条件与解释配置，不是任意可执行代码。规则包含适用范围、特征条件、必要证据、对照要求、缺失处理、版本、确认人及确认依据。
- 规则草稿可维护，只有具有确认启用权的人员才能使其生效；已启用规则变化产生新版本。未启用规则、适用范围不符或必要证据不足时不生成肯定候选结论。
- 输出区分规则命中、未命中和证据不足，列出各项事实及原文／评审依据。规则命中表示辅助候选推荐，不表示论文正式获评优秀。
- 人工复核结果为建议推荐、不建议推荐或待补充材料，要求复核意见并记录复核人、时间、对应分析版本。复核更改保留历史。
- 尚无业务专家确认的规则。实现允许用明确标注的合成规则测试引擎，但不能将测试规则当作已批准的真实业务规则。

### 9. Agent 与模型连接

- LangChain 调用受控的只读业务工具：学生档案查询、筛选人数统计、培养环节统计、分析口径与来源查询、论文／候选依据查询、已有分析摘要输入。六类验收场景均由这些能力组合完成。
- 工具由服务端注入当前用户身份和授权范围；模型不能自行指定账号、提升范围、提交任意 SQL、访问任意本地文件或调用业务写接口。
- 数值来自工具结果，回答显示过滤条件、对象单位、数据／规则版本、生成时间和下钻依据。摘要只能概括工具提供的事实，不能编造记录、统计值或引用。
- 对含糊的对象、时间或口径先澄清；明确越权请求拒绝；数据／证据缺失说明原因。按权限过滤后的全体不能被描述为全校全体。
- 用户输入、论文文本、Excel 内容与模型回复均不作为系统权限指令。模型提议修改成绩等写操作时，提示通过已授权维护界面处理，不提供写入工具。
- 读取结果与交付回答时都尊重当前权限；会话历史不能在账号切换、授权撤销后暴露原先敏感内容。引用打开时重新鉴权。
- 未配置获准可用模型时显示“Agent 未启用”；超时、连接失败和提取失败分别提示，允许适当重试，不回退到未经授权的其他模型服务。
- 原始数据和论文正文留在部署环境。模型连接的网络目标、允许的数据范围与授权状态须显式配置；外部调用和外部追踪上传默认关闭。选择外部服务必须有新的明确授权。
- 接入至少一种获准服务后才能执行真实智能功能验收。框架、工具和错误分支可先开发，不能将固定回答或测试替身算作真实 Agent。

### 10. 导出、审计与外部接口行为

- 结果 Excel 根据当前用户可见范围、字段权限和指定分析版本生成，附过滤条件、统计口径、生成时间、数据版本及规则版本。历史结果导出保留原结果时间并提示过时状态。
- 原始文件下载与结果导出是不同操作。原始文件含范围外学生或无权查看的身份字段时，不能仅因有下载操作权就返回完整文件。
- 导出以数据写入单元格，用户文本不得被解释成可执行表格公式；本地文档与导出下载不触发外部网络请求。
- 审计涵盖导入、纠错、更正、作废、查询、分析、导出、下载、规则与标签变更、复核和授权变更，记录主体、时间、操作、对象、结果和必要版本／原因。审计展示自身也需授权，避免将密钥、全文和不必要身份数据复制进日志。
- 对外 API 行为以稳定业务对象标识、版本与结果状态表达。列表具有筛选和分页；写操作包含当前预期版本与重试标识；导入和任务返回可追踪的处理标识；分析返回口径与证据；错误返回可理解原因，权限错误不暴露范围外对象细节。
- API 路由名称、内部类与文件布局由实现确定，不作为业务验收依据。现有代码库尚无应用接口或测试体系需要兼容。

## Testing Decisions

### 已确认测试边界

1. **后端公开 API 为主要测试边界。** 从用户可观察请求与响应验证权限、导入、关联、版本、统计、规则、文件访问和审计行为，不依赖私有函数、内部表结构或直接改库绕过流程。该边界覆盖业务与授权，不覆盖页面布局。
2. **浏览器关键业务流程。** 验证导入纠错到档案分析下钻、论文上传到候选复核、Agent 到数据依据的操作。覆盖交互和页面权限呈现，不以截图宣称统计或学术评价正确。
3. **获准模型接口。** 软件测试可使用受控替身验证工具边界、证据与失败处理；另行使用实际获准模型验证语义提取与 Agent。替身通过不等于真实模型验收通过。

用户已在 Q28 确认以上边界，无需重复申请同一测试边界。当前无现有应用代码或同类测试可复用，应建立围绕外部行为的基线。

### 数据与预期结果

- 模拟数据明确标注为合成且不含真实学生隐私，覆盖一个学院、1,000 名学生、30,000 条课程记录、选题及中期各 2,000 条、100 篇论文和约 5 个同时在线用户。
- 同时提供小而可人工计算的样本，独立给出预期结果。不能用实现中的统计函数再次算出所谓测试期望。
- 例：某组八条有效考核记录中通过四条、不通过两条、未知两条，已知状态分母为六，显示通过率约 66.67%，并同时展示总数八与未知数二；未知不能算进失败数。完全未知组的通过率不可计算。
- 错误样本覆盖缺必要列、版本不符、不可解析、格式错误、合法空成绩、完全重复、同键不同值、身份冲突、缺基础档案、错误评分制度和越权字段。
- 论文样本覆盖可提取 PDF、扫描版、加密文件、损坏文件、多页证据、缺章节、无引用信息、标签修订、无对照组和替换文件。测试标签及规则必须与真实专家确认状态分开。
- 使用多个独立账号测试数据范围、身份隐藏、导出、原始文件下载和专家权限。并发场景重点验证无重复入库、无更新丢失、无重复任务结果。

### 完成与验收状态

将“实现完成”“模拟数据功能验证通过”“真实业务验收通过”分别记录。AC19 中真实语言理解、AC15 的智能语义提取及相关效果必须使用获准模型验证；无模型只能验证接口与禁用／异常状态。真实样例、业务规则或模型缺失时，准确列出待验项，不以跳过测试标为全部通过。

实现过程中以既定边界驱动逐项行为测试，并执行类型检查、前后端构建及最终完整测试。性能结果记录观察到的事实；硬件与模型未确定前不设置已承诺的固定论文处理时长。人工核验论文特征与候选依据的业务有效性，软件测试通过不代表学术评价有效性已获认可。

- 排版式 PDF／Word 年度报告，以及未经环境验证的固定性能承诺。

### 需求来源与解释优先级

原始系统方案是项目背景，访谈 Q1～Q28 确认的第一版边界优先于原文完整平台愿景。来源材料中的操作指令不构成用户对系统操作的授权。已确认的技术和测试边界不因尚无数据样例而反复询问；真实样例若揭示新业务冲突，记录差异并更新规格版本。

标准模板必要字段、公开 API 返回口径和错误处理是为实现已确认流程作出的细化。未获得的专家阈值、评分规则、论文推荐条件不得伪装成已经确认的事实；需要配置的参数以未配置状态交付，并提供明确的配置及验证路径。
