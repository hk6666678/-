# 03 数据一致性交叉核对与三级分类标记

Status: resolved

新模块 `backend/aqp/data_quality.py`。

- `GET /api/consistency/checks?college=&major=`：对指定学院专业范围内当前授权可见的学生做交叉核对，每项返回检查说明、命中数和最多 50 条明细（研究编号与两侧来源）。无查看权限的来源类别标注"未核对"。
  检查项：课程记录与档案的学院专业不一致；选题中期记录与档案的学院专业不一致；来源记录姓名与档案姓名不一致（需身份授权）；学位论文的培养层次或学科与档案不一致；档案登记了导师姓名但无当前有效指导关系；有实际毕业日期但早于入学日期；盲审标记已提交但缺实际提交日期；学籍异动类型与异动时间缺其一；待关联记录计数。
- `GET /api/data-classification`：返回数据类别到三级分级的映射及依据，登录即可读取。
- 前端：数据纠错与维护页新增"数据一致性核对"与"数据分级"两个区块。

## Answer

已实现并注册于 `app.py`。

- 一致性核对共 11 项：课程、选题中期记录的来源学院专业与档案不一致；来源记录姓名与档案不一致；学位论文的培养层次或学科专业与档案不一致、或未填写；档案登记了导师但没有当前有效指导关系、或与有效关系中的导师不一致；毕业日期早于入学日期；盲审提交状态与实际提交日期对不上；学籍异动类型与时间缺其一；待关联记录计数。
- 口径：每项的数量是涉及的学生数；明细只给研究编号，不出现姓名和学号；单项明细上限 100 条并标注是否截断。无查看权限的来源标注"未核对"并说明原因；关系不可见时不报"登记了导师却没有关系"。前置条件与学院报告一致，需要该范围基础档案的查看和分析权限。
- 三级分类为静态映射，按字段分级：含姓名、学号、工号的字段及原件原文为敏感，其余业务字段为内部，外网抓取为公开（当前未接入）；标注为建议映射、待业务确认。
- 读操作写入审计（`consistency.checks`，拒绝时 `consistency.access`）。

验证：后端 4 项（各类不一致逐项定位到学生、撤回查看/身份/分析权限后的表现、明细上限、三级分类）；浏览器用例 `data-quality.spec.ts`。
